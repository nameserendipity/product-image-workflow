# 抖音 SKU 截图参考设计

## 目标

支持 Excel 中“抖音商品链接 + SKU 截图”的输入形式：从截图中提取真实 SKU 名称、颜色、规格、价格和缩略图；清晰缩略图作为对应 SKU 的视觉参考，模糊缩略图只保留可确认的文字数据，不编造商品细节。

## 约束

- 抖音采集包可能没有 SKU 图片，截图是唯一的 SKU 视觉来源。
- 截图中的文字数据不得被生图模型改写或补造。
- 缩略图只允许普通裁剪和尺寸调整，不使用 AI 超分辨率创造细节。
- SKU 最多生成 8 张，数量以截图中可验证的 SKU 条目为准。
- 淘宝、天猫、京东现有输入和生成链路保持不变。

## 数据流

1. 读取 Excel 行：识别一个 HTTP 商品链接和同一行的本地截图路径、`file:///` 路径或嵌入图片。
2. 采集抖音商品素材和商品参数。
3. 视觉模型分析截图，输出每个 SKU 的文字字段、缩略图坐标、清晰度判断和置信度。
4. 程序按坐标裁剪缩略图，校验尺寸和清晰度，保存到当前商品目录。
5. 合并为 `sku_variants`：真实字段始终保留；参考来源记录为 `screenshot_thumbnail` 或 `main_product_fallback`。
6. SKU 工作流逐条使用对应裁剪图；不可用时使用商品主图并标记 `low_visual_confidence`。
7. 导出 SKU 表时增加参考来源、视觉置信度和降级原因，不影响已有字段。

## 质量门槛

- 坐标必须在截图边界内，且裁剪区域至少为 64x64 像素。
- 模型明确判定模糊、遮挡、无法对应 SKU 或置信度低于 0.65 时，缩略图不可作为视觉参考。
- 裁剪失败不阻断商品任务；该 SKU 继续保留参数并使用商品主图降级生成。
- 不能确认的文字字段留空，`parse_status` 标记为 `low_confidence`，禁止静默猜测。

## 失败处理

- 截图路径失效：记录 `sku_screenshot_missing`，不生成虚假 SKU 数据。
- 视觉接口失败：保留采集到的商品数据，SKU 任务失败原因写入日志和导出状态。
- 某个 SKU 裁剪失败：只影响该 SKU，不影响其它 SKU 和主图/详情图。

## 验收标准

- 无表头的 A 列链接、B 列 `file:///` 截图能被识别为一个直链商品任务。
- 截图中 2 个 SKU 能得到 2 条参数记录，清晰缩略图被绑定到对应 SKU。
- 低清缩略图不会进入生图输入，且导出记录低视觉置信度。
- 抖音没有原始 SKU 图时，SKU 工作流仍能按截图识别数量运行。
- 现有批量链接、单链接和非抖音回归测试保持通过。
