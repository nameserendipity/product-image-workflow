# 对标商品直接创作与侧边栏改版设计

**状态：** 已确认，待实施
**日期：** 2026-08-11
**提交策略：** 本轮属于实验改动，设计文档和后续实现均保持未提交，除非用户另行要求。

## 目标

在保留“上传我方产品图并替换商品主体”能力的同时，增加“不上传我方产品图，直接参考对标商品创作”的模式。直接参考模式保留对标商品的外观结构、比例、颜色、材质和主要部件，删除品牌、Logo、店铺名、水印及违规信息，并让详情图覆盖更多角度和局部细节。

前端改为按任务入口组织的侧边栏工作台，首版只显示“链接生图”和“表格生图”。

## 非目标

- 本轮不重新设计 SKU 图片与规格、颜色、价格的关联算法。
- 本轮不新增美工 Agent、详情图 Agent 或模型与 OSS 设置入口。
- 本轮不改变表格生图现有业务链路。
- 本轮不取消上传我方产品图的现有替换模式。
- 本轮不自动打包，也不提交 Git。

## 前端信息架构

左侧固定侧边栏只包含两个可用入口：

1. 链接生图
2. 表格生图

链接生图采用“任务操作优先”布局：

- 主区域固定展示生成模式、对标链接、工作流选择、数量规则和执行进度。
- 右侧保留任务 Agent，用于解释状态、回答问题和处理中途停止指令。
- 不让关键任务参数被聊天记录遮挡。

链接生图页面顶部提供显式两段式模式选择：

- `直接参考对标商品`
- `使用我方产品图`

不能根据“是否存在历史上传图片”自动推断模式。切换到直接参考模式后，即使会话中保留旧产品图，也必须忽略该图片。

## 生成模式

后端新增持久化字段：

```text
generation_mode:
- own_product
- competitor_reference
```

### 使用我方产品图

- 产品图必填。
- 产品图是唯一商品身份来源。
- 对标图片只提供构图、场景、光线、道具和信息层级参考。
- 保持现有替换工作流和商品真实性约束。

### 直接参考对标商品

- 产品图可为空。
- 第一张有效对标主图是整体商品身份锚点。
- 其他已采集主图、SKU 图和详情图用于补充侧面、背面、结构与局部细节。
- 生成结果保留对标商品的结构、比例、颜色、材质和主要部件。
- 删除对标品牌、Logo、店铺名、平台水印和违规信息。
- 普通卖点保留原有信息层级和版式作用，但改写为通用、可验证的文案，不直接复制竞品原文。

## 身份图解析

生成器内部继续接收一个明确的身份图路径，不把空路径传入底层模型：

```text
own_product          -> 用户上传的产品图
competitor_reference -> manifest 中第一张有效主图
```

如果直接参考模式没有采集到主图，则停止生成并提示“缺少商品身份主图”。不能使用 SKU 图或详情图冒充整体身份图。

## 多视角商品档案

详情图生成前增加两阶段视觉分析。

### 第一阶段：逐图并发分析

对所有已采集主图、SKU 图和详情图并发提取：

- 可见角度
- 商品轮廓与比例
- 颜色和材质
- 真实可见部件
- 正面、侧面、背面和局部信息
- 标签、品牌、水印和高风险内容
- 无法确认的信息

单张分析失败时跳过该图，不中断整批任务。

### 第二阶段：身份汇总

视觉模型将逐图结果汇总为统一商品档案：

- 第一张主图锁定整体身份。
- 其他图片只补充第一张图不可见的真实信息。
- 冲突信息以第一张主图优先，并在档案中记录不确定项。
- 不根据文字或类别常识凭空增加结构。

## 详情图规划

详情图数量沿用现有 `6 <= detail <= 15` 规则。视觉模型根据商品实际结构动态规划不同主题，不写死特定商品类别。

候选主题包括：

- 正面整体展示
- 45 度立体展示
- 侧面展示
- 背面展示
- 材质和纹理特写
- 做工与连接处特写
- 关键部件或功能区域
- 尺寸、结构或使用场景

规划器需要避免连续生成重复正面图。某一角度没有可靠信息时，优先改用材质、局部或结构特写。

每张详情图最多使用三类输入图片：

1. 第一张主图，统一商品身份。
2. 与目标角度最匹配的补充图片，提供真实结构。
3. 当前详情参考图，提供布局、场景和信息层级。

重复路径在提交模型前去重。

## 受限角度推断

当全部采集图片均未展示目标侧面或背面时，允许模型进行受限推断：

- 可以生成合理的侧面、背面、材质和体积关系。
- 禁止新增接口、按钮、口袋、开口、配件、控制器和其他结构性部件。
- 无法可靠推断时，改为真实可见区域的局部特写。
- 使用推断角度的结果写入 `inferred_view=true`。
- 前端和生成记录将该结果标记为人工重点审核。

## 提示词策略

视觉分析和生图提示词按 `generation_mode` 分开，不复用“我方商品是唯一身份来源”的固定文案。

直接参考模式必须要求：

- 保持商品结构、轮廓、比例、颜色、材质和主要部件。
- 删除品牌、Logo、店铺名、平台水印和竞品专属标识。
- 删除专利、认证、医疗、绝对化、虚假数据和来源国家等高风险信息。
- 保留普通文字区域的版式作用，重新生成通用、可验证卖点。
- 不复制竞品普通卖点原文。
- 不新增无法从图片确认的商品参数或功效。
- 详情图遵守多视角商品档案和受限推断规则。

## 数据流

```text
选择链接生图
-> 选择生成模式
-> 输入对标商品链接
-> 店透视下载全部图片（多文件）
-> 解压、分类、去重并写入 manifest
-> 解析统一身份图
-> 并发分析全部采集图片
-> 汇总多视角商品档案
-> 规划主图、SKU 图和详情图任务
-> image-2 并发生成
-> OSS 上传生成结果
-> 人工审核
```

## 状态与恢复

会话文件保存：

- `generation_mode`
- 对标链接
- 工作流选择
- 数量规则
- manifest 路径
- 可选产品图路径
- 多视角商品档案路径或内容摘要
- 生成进度和结果

服务重启后必须按保存的 `generation_mode` 恢复，不能因为旧产品图仍存在而切换模式。

## 异常处理

- 没有主图：直接参考模式停止生成，保留采集结果。
- 只有一张主图：允许生成，未展示角度按受限推断处理。
- 单张视觉分析失败：跳过该图，继续其他图片。
- 多视角汇总失败：主图和 SKU 工作流可以继续；详情图工作流单独停止。
- 某类采集图片不存在：只运行有实际素材的工作流。
- 用户停止生成：取消尚未开始的分析和生图任务，保留已完成结果。

## 测试设计

### 状态测试

- 双模式可以显式切换并持久化。
- 直接参考模式忽略历史产品图。
- 上传模式缺少产品图时阻止生成。
- 直接参考模式缺少主图时阻止生成。
- 服务重启后恢复正确模式。

### 身份解析测试

- 上传模式选择用户产品图。
- 直接参考模式选择第一张有效主图。
- 无主图时不回退到 SKU 或详情图。

### 多视角测试

- 所有有效采集图片进入逐图分析任务。
- 单图失败不阻断汇总。
- 汇总结果保持第一张主图优先级。
- 详情图规划不会全部重复同一正面角度。
- 无真实角度时结果带 `inferred_view=true`。

### 模型请求测试

- 上传模式保持产品图在身份输入首位。
- 直接参考模式保持第一张主图在身份输入首位。
- 匹配角度补充图和详情参考图按顺序传入并去重。
- 两种模式使用不同提示词约束。

### 前端测试

- 侧边栏只显示链接生图和表格生图。
- 链接生图默认清晰展示模式选择、链接、工作流和进度。
- 直接参考模式不显示产品图必填错误。
- 上传模式恢复产品图上传与必填校验。
- 任务 Agent 保留在右侧，不遮挡主要任务参数。

## 验收标准

1. 用户可以在不上传产品图的情况下完成链接采集、分析和生成。
2. 直接参考模式统一使用第一张主图锁定商品整体身份。
3. 详情图使用全部采集素材建立多视角商品档案。
4. 详情图在 6 至 15 张内尽量覆盖不同角度和细节。
5. 推断角度不新增结构性部件，并带人工审核标记。
6. 生成结果删除品牌、Logo、水印和违规信息。
7. 普通卖点不复制竞品原文，而是生成通用、可验证表达。
8. 原有上传产品图替换模式保持可用。
9. 表格生图现有链路不受影响。
10. 所有新增及现有回归测试通过后才能交付实验版本。
