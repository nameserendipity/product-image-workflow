# 抖音链接与批量产品替换设计

## 目标

在现有商品图片工作台中增加两项能力：

1. 单个链接和批量链接表格支持抖音商品链接，并继续支持“仅采集”和“采集、生成、导出”两种运行模式。
2. 在“链接生图”的批量入口增加“产品图批量替换”模式。程序从表格中识别每个商品对应的我方产品图和对标商品链接，直接采集指定链接，再复用单链接 `own_product` 生成链路完成替换、OSS 上传和独立 Excel 导出。

本次不修改“表格生图”的图片搜同款逻辑，也不创建新的侧边栏入口。

## 功能边界

### 链接生图

“链接生图”继续包含“单个链接”和“批量链接表格”两个入口。

单个链接支持淘宝、天猫、京东和抖音。用户可以选择：

- 参考对标商品创作。
- 使用我方产品图替换。

批量链接表格增加两个明确模式：

- `direct_link`：按链接采集并参考对标商品创作。
- `direct_replace`：按链接采集，并使用表格中与该链接配对的我方产品图替换。

两个批量模式都支持仅采集、完整运行、停止、继续和断点恢复。

### 表格生图

“表格生图”继续执行现有“读取商品图 -> 淘宝搜同款 -> 按销量采集 -> 生图 -> 导出”流程。本次不修改其输入语义和采集策略。

## 前端位置

新功能放置在：

```text
链接生图
└─ 批量链接表格
   ├─ 参考对标商品创作
   └─ 产品图批量替换
```

使用分段控件切换批量模式，不新增页面或侧边栏项目。

选择“产品图批量替换”后，上传区显示简短输入要求：表格每个有效商品必须能够识别出一张我方产品图和一个受支持的商品链接。上传完成后显示：

- 有效商品数。
- 缺少商品图数。
- 缺少链接数。
- 不支持平台数。
- 图片或链接配对冲突数。

用户确认后才能开始批处理。运行中继续复用现有批次进度、停止、继续和打开文件夹控件。

## 表格识别

### 表头模式

程序扫描所有非空工作表的前 10 行，优先识别以下字段：

- 我方商品图：`商品图`、`产品图`、`我方商品图`、`1688商品图`。
- 对标链接：`商品链接`、`对标链接`、`竞品链接`、`URL`、`淘宝链接`、`天猫链接`、`京东链接`、`抖音链接`。
- 可选 SKU 字段：`SKU名称`、`颜色`、`规格`、`价格`、`SKU参考图`。
- 可选普通字段：`标题`、`商品标题`、`名称`、`运费`、`备注`。

表头匹配忽略大小写、首尾空格、换行和常见全角半角差异。

### 无表头模式

没有可识别表头时，程序逐行扫描：

1. 从单元格值或超链接中识别淘宝、天猫、京东或抖音 URL。
2. 从普通 Excel 图片、WPS `DISPIMG` 单元格图片和对应媒体关系中识别图片。
3. 同一行恰好包含一张图片和一个受支持链接时，形成一个商品任务。
4. 空行跳过，但保留原工作表名称和行号。
5. 同一行出现多张候选商品图或多个候选链接时，标记为配对冲突，不使用相邻行、距离或版面位置猜测。

程序扫描所有非空工作表，并按工作表顺序、原始行号顺序生成任务。

### SKU 行分组

当表格提供 SKU 字段时，同一商品可以占多行。相同标准化商品链接的连续行归为同一商品，采集只执行一次。每行 SKU 数据保留以下来源状态：

- `collected`：来自平台或店透视的真实 SKU 数据。
- `manual`：来自用户表格填写。
- `text_conditioned`：只有用户填写的名称、颜色或规格，没有 SKU 参考图。
- `reference_image`：用户同时提供 SKU 参考图。
- `missing`：没有可验证 SKU 数据。

不把其他平台的 SKU 名称、价格或规格混入抖音商品。

## 平台识别与短链解析

链接识别新增抖音平台：

- `v.douyin.com` 短链。
- `haohuo.jinritemai.com` 商品详情链接。
- 能解析到上述详情页的抖音分享链接。

抖音短链先解析最终地址，再提取商品 ID。解析失败、不是商品详情页或缺少商品 ID 时，单行标记失败；批次继续处理下一行。

不把未知平台降级到淘宝图片搜同款。

## 抖音采集器

### 浏览器与店透视

抖音采集使用现有隔离采集浏览器、持久化用户目录和动态 CDP 端口。不得硬编码本机测试端口 `57377`，也不得复用用户日常浏览器的首个标签页。

采集器必须：

1. 等待 CDP `/json/version` 和 Playwright 连接同时就绪。
2. 在已有浏览器上下文中新建独立标签页。
3. 打开标准化抖音商品详情地址。
4. 等待店透视面板出现并加载正确商品 ID。
5. 设置主图、主图视频、详情图、商品数据和商品参数选项。
6. 触发店透视多文件资料下载。
7. 等待下载文件完整保存，而不是只检测第一个下载事件。
8. 结束时仅关闭采集器创建的标签页，不关闭浏览器。

登录、验证码、平台风控或店透视未登录时，采集器停止点击、滚动和刷新，并进入现有暂停语义。用户完成验证后可继续当前商品。

### ZIP 解包与分类

店透视抖音资料 ZIP 下载完成后，采集器使用结构化 ZIP 和 Excel 读取方式处理：

- `主图/` -> `main`。
- `详情图/` -> `detail`。
- 主图视频文件 -> `main_video_local_path`。
- 商品数据工作表 -> 标题、商品 ID、品牌、类目、商品级价格、销量和店铺字段。
- 商品参数工作表 -> `parameters`。

每个素材计算稳定路径、类型、来源文件名和状态，并写入统一 schema v2 manifest。采集原图只保存在本地，不上传 OSS。

### 抖音 SKU 限制

当前实测抖音桌面 H5、店透视抖音资料表和详情接口没有稳定返回 SKU 名称、颜色、规格、组合价格、SKU ID 或 SKU 图片。因此：

1. 不根据商品标题、主图或详情图自动编造 SKU。
2. 平台没有 SKU 数据、表格也未补录时，SKU 工作流标记为 `missing` 并跳过。
3. 表格补录 SKU 名称、颜色、规格和价格后，可以按用户提供的数据创建 SKU 生成任务。
4. 有 SKU 参考图时，参考图参与当前 SKU 的身份约束。
5. 只有文字条件时，结果标记为 `text_conditioned`，不能标记为平台真实 SKU。
6. 没有真实或用户补录依据时，不生成固定数量的伪 SKU 图。

## 视频 URL

优先保留可直接访问的原视频 URL。抖音资料包只有本地 MP4 且无法提取原 URL 时：

1. 使用现有 OSS 配置上传 MP4。
2. 根据扩展名设置正确内容类型。
3. 将 OSS 公网 URL 写入 manifest 和导出表格。
4. 上传失败时保留本地路径和明确错误状态，不能把任务标记为完整成功。

## 批量产品替换

### 任务模型

新增 `direct_replace` 批次模式。每个任务至少包含：

- 工作表名称和原始行号。
- 我方产品图本地路径。
- 原始链接和标准化链接。
- 平台和商品 ID。
- 可选标题、SKU 数据、SKU 参考图和原表字段。

我方产品图提取到批次 `source-images` 目录，manifest 保存稳定相对关系，便于断点恢复和跨电脑发布包运行。

### 采集策略

`direct_replace` 与 `direct_link` 共用平台分流和直接链接采集器：

- 淘宝、天猫、京东调用现有店透视直接链接采集器。
- 抖音调用新增抖音店透视采集器。

每个链接只采集其指定商品，不搜索第二款商品，不执行淘宝搜同款，不混入其他商品素材。

### 生成策略

`direct_replace` 不维护独立提示词，直接复用单链接“使用我方产品图”即 `own_product` 模式的分析、任务编排和 `WorkflowRunner`：

1. 当前表格商品图是该任务唯一商品身份来源。
2. 对标主图、SKU 图和详情图分别作为构图、角度、背景、道具和版式参考。
3. 对标图存在商品主体时才执行商品替换；没有商品主体时不得强行插入我方商品。
4. 每张生成图必须保持我方商品可验证的结构、轮廓、比例、材质、颜色和关键部件。
5. 不把对标商品品牌、Logo、店铺名、水印、专利、认证或违规文案迁移到结果。
6. 主图、SKU 图和详情图继续使用现有类型专属提示词、数量设置和并发策略。
7. SKU 图继续保持无营销文案、背景符合商品定位；手工 SKU 字段只约束当前 SKU 任务。
8. 每行商品身份和分析结果相互隔离，不能串用前一商品的产品图或提示词。

用户明确指定生成数量时优先使用用户设置；没有指定时使用现有默认值和上下限。

## 生成结果与导出

每个有效商品继续导出一个独立 Excel，至少包含：

- 原工作表、原始行号和原始商品链接。
- 来源平台、商品 ID 和采集状态。
- 我方产品图来源。
- 对标商品标题、商品级价格和参数。
- 主图、SKU 图和详情图生成结果及 OSS URL。
- SKU 名称、颜色、规格、价格、来源状态和 SKU 参考图状态。
- 原视频 URL或 OSS 视频 URL。
- 缺失类型、警告、失败原因和处理状态。

生成图片数量只统计实际成功且文件存在的结果。分析或生成全部失败时不能导出空表并标记成功。视频上传失败或必需导出步骤失败时，商品状态保持失败或待恢复。

## 进度、暂停与恢复

两个新增场景复用现有 `batch-results.json` 和批次事件格式：

1. 任务状态包括待处理、采集中、已采集、生成中、导出中、完成、暂停、失败和停止。
2. 已完成商品永久跳过。
3. 已采集但未完成生成或导出的商品从现有 manifest 继续，不重新采集。
4. 用户主动停止时保留浏览器和已下载素材，不自动重启采集。
5. 平台验证暂停整个批次，并保留当前商品序号。
6. 更换输入表格后按文件身份创建新批次，不继承旧表进度。

## 错误处理

- 链接解析失败、缺图、缺链接、配对冲突和不支持平台：记录单行错误并继续。
- 店透视未加载、登录或风控：暂停批次等待用户处理。
- ZIP 缺少某类素材：已有类型继续，缺失类型跳过，不以其他类型伪装。
- 图片分析、生图、OSS 或 Excel 导出失败：按现有重试策略执行；重试耗尽后记录失败。
- 抖音无 SKU：不是采集器异常，但必须写入 `missing` 状态和用户可见警告。

## 实现边界

推荐新增抖音平台适配器和 `direct_replace` 批次模式，同时复用现有公共能力：

- `DirectLinkCollector` 的批次进程管理。
- `WorkflowRunner`、视觉分析和生成提示词。
- OSS 上传器。
- Excel 导出模型。
- 批次暂停、停止、继续和断点恢复。

不把抖音 DOM、ZIP 目录和数据表解析塞入淘宝/京东采集代码，也不复制单链接生成提示词。

## 验收标准

1. 单个抖音短链可以解析商品 ID，采集主图、详情图、视频、商品数据和参数，并生成统一 manifest。
2. 批量链接表格可以混合淘宝、天猫、京东和抖音链接，按原顺序处理。
3. 批量链接支持仅采集和完整运行，停止后可以从当前未完成商品继续。
4. “产品图批量替换”能识别表头列和无表头同一行图片/链接配对。
5. WPS `DISPIMG` 图片和普通 Excel 内嵌图片都能提取。
6. 配对不明确时明确报错，不猜测相邻图片或链接。
7. 每个替换任务复用单链接 `own_product` 生成链路，商品身份不跨行串用。
8. 对标图没有商品主体时，不强行插入我方商品。
9. 抖音无 SKU 数据时不生成虚假 SKU；用户补录 SKU 后按来源状态生成和导出。
10. 抖音本地 MP4 无原 URL 时上传 OSS，并在 Excel 中写入可访问 URL。
11. 生成图上传 OSS，采集原图只保存在本地。
12. 每个商品导出独立 Excel，所有成功状态都有实际生成图片或明确的仅采集结果作为证据。
13. 现有淘宝、天猫、京东单链接、批量链接和图片搜同款流程不发生行为回归。
