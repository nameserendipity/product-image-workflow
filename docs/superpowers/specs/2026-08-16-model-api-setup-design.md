# 模型 API 首次配置设计

## 目标

网页首次打开时，如果视觉模型或生图模型 Key 缺失，立即显示阻断式配置弹窗。用户保存成功后，Key 持久化到本机配置，后续刷新页面和重启服务都无需重复输入。

## 数据与安全边界

- Key 仅从浏览器提交到本地后端，不进入前端构建文件、日志、会话文件或状态接口。
- 后端将 Key 保存到已被 `.gitignore` 忽略的 `local_settings.json`。
- 保存时读取现有 JSON，只更新 `vision_api_key` 和 `image_api_key`，保留 API 地址、OSS 和浏览器配置。
- 使用同目录临时文件加 `os.replace` 原子写入，避免写入中断破坏配置。
- `/api/status` 只返回 `vision_api_ready` 和 `image_api_ready` 布尔值。

## 启动与保存流程

1. `AppState` 初始化时从 `local_settings.json` 恢复两个模型 Key。
2. 页面首次获得状态后，如果任一 Key 未就绪，打开不可跳过的配置弹窗。
3. 用户输入两个 Key 并保存，`POST /api/api-keys` 验证非空、原子写入配置，再更新当前进程内存。
4. 保存接口只返回就绪状态，不返回 Key。
5. 保存 Key 不触发采集、生图或其它工作流。

## 界面

- 顶栏增加始终可见的“模型 API”状态按钮，使用红色“未配置”或绿色“已配置”状态。
- 未配置时自动弹出居中模态框，背景遮罩阻断工作流操作。
- 弹窗内包含视觉模型 Key、生图模型 Key 两个密码输入框和“保存并继续”按钮。
- 已配置后可从顶栏入口重新打开弹窗更换 Key；重新配置窗口允许关闭。
- 保留原侧栏配置入口，但统一打开同一个弹窗，避免重复表单逻辑。

## 验收标准

- 缺失任一 Key 时，页面首次加载自动弹窗。
- 两个 Key 保存成功后，本次服务立即就绪，刷新和服务重启后仍就绪。
- 保存不会覆盖 `base_url`、`browser_choice` 或 `oss`。
- 状态接口和保存响应不包含真实 Key。
- 不重启当前运行服务完成代码修改和验证。
